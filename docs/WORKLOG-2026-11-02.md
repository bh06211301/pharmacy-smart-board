**小插曲 3（隔天追加測試時又發現一個，field.html 的導航地圖壞了）**：使用者後續要求「field.html
也用這把 key，去正式網站測一次」，測了才發現**「開始今日導航行程」的嵌入地圖壞了**，錯誤訊息
「Google Maps Platform rejected your request. This API is not activated on your API
project」。查程式碼發現 `field.html` 兩處（`nav-dest-map`）用的是 **Google Maps Embed API**
（`https://www.google.com/maps/embed/v1/directions?...`），網域是 `www.google.com` 不是
`maps.googleapis.com`，路徑也不是 `/maps/api/...`，之前兩輪稽核用的搜尋字串都沒掃到這個模式，
這是第三個漏掉的 API。而且這次原因不是白名單沒列到（`maps-embed-backend.googleapis.com` 其實
已經補進 key 的 `--api-target`），是**整個 `appsheets-gps` 專案根本沒啟用這個服務**（
`gcloud services list` 查過，另外 4 個 API 都在已啟用清單裡，唯獨這個不在——API 限制清單只能
「允許已啟用的服務」，不會自動啟用服務，這點跟帳單警示那次要先 `gcloud services enable
billingbudgets.googleapis.com` 是同一種坑）。補 `gcloud services enable
maps-embed-backend.googleapis.com --project=appsheets-gps` 後，Playwright 截圖確認嵌入地圖
正常顯示真實路線（34分鐘/33.7公里）。**這次學到的教訓：用純文字搜尋程式碼找「用了哪些 API」
不夠可靠，要真的把每個會跳出地圖/算路線的功能都點過一次才能抓到全部用法——這三次漏掉的分別是
`routes.googleapis.com`（REST fetch，但網域符合預期模式卻沒被我原本的搜尋字串覆蓋）、
`maps-embed-backend.googleapis.com`（網域完全不同模式）。**
