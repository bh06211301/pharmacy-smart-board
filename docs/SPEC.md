> 設計稿：Claude Design 畫布「SmartRoute 風格提案」的 A0～A10（灰階線框，只定版面與流程，不定視覺風格）

## 0. 給 Claude Code 的工作原則

1. 每個階段開始前，先列出「要新增或修改的檔案」與「Sheet 要新增的欄位或分頁」，等我確認後再動手。
2. 只在 `planner-v2` 分支工作。GitHub Pages 讀 main，現有的 `index.html`、`tasks-page.html`、`recommend.html` 在新版穩定前保持可用，不要改動。
3. 新頁面另開檔案（例如 `planner.html`），不要覆蓋舊頁。
4. AppSheet 正在使用的表（新客戶資料表、拜訪紀錄、訂單主檔），**只能新增欄位，不能改欄名、刪欄或改順序**。要改結構時先問我。
5. 交付完整可貼上的檔案，不要只給片段 diff。
6. 規則或參數（間隔天數、加分、半徑）一律集中在一個設定檔，不要寫死在程式裡。

## 1. 要解決的問題

現在系統裡三個功能是分開的：

| 現有功能 | 位置 | 問題 |
|---|---|---|
| 月曆排程 | `index.html` 月曆 | 要手動把店排進某天，實際上沒在用 |
| AI 評分推薦 | `recommend.html` | 只排名，不知道今天會去哪一區，推薦不具體 |
| 路線規劃 | `tasks-page.html` | 選好店才算路線；油費估算沒有實際用處 |

實際的使用情境：

- **每天早餐時在電腦上規劃**。老爸會說今天要送哪幾家，這些店就是當天的「錨點」，其他店是繞著錨點補進去的。
- 起點和終點每天固定：汐止辦公室出發（約 13:30），收工回內湖（目標 17:30 前）。
- 每天約 3 家陌生開發，來源是新開藥局篩選器裡標「要去」的店。
- 藥師的特殊規則（例如週一不能去）現在只記在腦中，容易忘記。
- 週五自動排的下週草稿目前沒有發揮作用，**不以週計畫為核心**。
- 評分最看重兩件事：**多久沒去**、**有沒有待追蹤事項**。叫貨金額只在同分時用來決定先後。
- **拿掉油費估算**，改成顯示預估收工時間。

## 2. 核心流程

```
早餐：輸入今天一定要去的店（錨點）
  → 系統在錨點附近推薦順路可補的店（依分數排序，標出推薦理由與規則衝突）
  → 勾選加入，違反「擋住」類規則時跳出選項
  → 自動排順序，顯示預估收工時間
  → 確定，送到手機外勤模式
```

月曆不再負責每天排店，只放「指定日期的事」（約好的、請款日、有期限的待追蹤）和「每天跑哪一區」。

## 3. 資料結構

### 3.1 總覽

| 表 | 放什麼 | 動作 |
|---|---|---|
| 新客戶資料表_AppSheet（現有） | 正式客戶基本資料 | 新增 1 欄（選配） |
| 藥局每日異動追蹤 › 篩選分頁（現有） | 新店的開發階段 | 新增 3 欄 |
| 店家規則（新） | 每家店的規則，一家可多條 | 新建分頁 |
| 待追蹤（新） | 掛在店上的待辦，做完就結案 | 新建分頁 |
| 拜訪紀錄（現有） | 每次拜訪，包含新店的「記結果」 | 新增 1 欄（選配） |
| 客戶狀態（現有，死客戶） | 停止往來標記 | 不改，規劃時排除 |
| 訂單主檔（現有） | 出貨、貨運公司 | 不改，只讀 |

店家一律用**店家代號**關聯。新店在轉正式前還沒有店家代號，用篩選分頁的列 ID 關聯（見 3.3）。

### 3.2 新客戶資料表（現有）

| 新增欄位 | 型別 | 說明 |
|---|---|---|
| 建議間隔天數 | Number，可空白 | 選配。空白就用階段預設的 21 天；重點客戶可填 14 |

客戶資料表裡現有的規則備註（請款日、哪天不要去）**不用刪**。第 1 階段寫一次性腳本，把它們轉成「店家規則」表的格式讓我確認，確認後舊欄位保留但不再使用。

### 3.3 藥局每日異動追蹤 › 篩選分頁（現有）

在現有欄位右側新增：

| 新增欄位 | 型別 | 範例 | 說明 |
|---|---|---|---|
| 目前階段 | Enum | 初訪後 | 發現／初訪後／二訪後／試賣中／轉正式／放棄 |
| 進入階段日期 | Date | 2026/10/11 | 每次階段改變就更新，用來算倍數 |
| 放棄原因 | Text | 已有固定廠商 | 只有放棄時才填 |

規則：

- 我在篩選頁標「要去」時，自動把「目前階段」設成「發現」、「進入階段日期」設成當天。
- 同一家店可能因依序申請而重複出現，**用地址去重**，只對其中一列記階段。
- 轉正式時：在新客戶資料表建一筆、配店家代號，篩選分頁那一列保留不刪，作為開發歷程。
- 現有的「已排日期」欄位保留，照舊運作。

「排程處理」決定系統的反應：

| 值 | 系統行為 | 例子 |
|---|---|---|
| 擋住 | 規劃日落在禁止範圍時，推薦清單把該店變灰；手動加入時跳出規則衝突對話框（A4） | 週一不拜訪 |
| 提醒 | 不影響排程，出現在出發前提醒清單和藥局檔案 | 送貨前先 LINE 告知 |
| 自動調整 | 自動調整拜訪順序避開時段，調整後告訴我，可以復原 | 15:00 後藥師才在 |

固定要建立的提醒（目前記在腦中的）：

- 去老爸的藥局送貨時，要把帳單還給老爸。
- 去老爸的藥局請款時，收到的錢要交給老爸。

## 4. 評分

### 4.1 建議回訪間隔

| 階段 | 建議間隔 | 起算日 |
|---|---|---|
| 發現 | 7 天內初訪 | 進入階段日期 |
| 初訪後 | 10 天內二訪 | 進入階段日期 |
| 二訪後 | 14 天內談試賣 | 進入階段日期 |
| 試賣中 | 14 天回訪看銷況 | 進入階段日期 |
| 正式客戶 | 21 天（客戶資料表有填「建議間隔天數」就用該值） | 最後一筆拜訪紀錄日期 |

### 4.2 公式（初版，參數放設定檔）

```
倍數 r = 距起算日天數 / 建議間隔

間隔分 = min(r, 2.0) × 50                     → 0～100

待追蹤分 = 各筆未完成待追蹤加總，上限 40
  指定日期前，剩 3 天內（含逾期）   +30
  指定日期前，剩 4～7 天            +20
  指定日期前，剩 8 天以上           +10
  下次經過                         +10

總分 = round(間隔分 + 待追蹤分)
同分時：近 12 個月叫貨金額高的優先
```

### 4.3 推薦清單的篩選

1. 排除死客戶（客戶狀態表）。
2. 只列出距離任一錨點 **2 公里內** 的店（半徑可在畫面上切換，預設 2 公里）。
3. 規劃日違反「擋住」規則的店：**照樣列出但變灰**，標示規則內容。
4. 每家顯示推薦理由，例如「正式客戶　23 / 21 天 = 1.1 倍，葉黃素要追」。

### 4.4 顏色分級（客戶總覽、地圖共用）

| 倍數 | 標示 |
|---|---|
| 1.5 以上 | 很久了（深紅） |
| 1.0～1.5 | 該去了（淺紅） |
| 0.5～1.0 | 快到了（淺灰） |
| 0.5 以下 | 還早（白） |

### 5.2 A1 今天（清單）

三欄由左到右：

1. **今天一定要去**：上方兩週小日曆（點日期切換規劃日；選中店家的禁止日變灰）。輸入框可輸入「福安 送 2 箱」新增錨點。下方列出系統偵測到今天到期的事（請款日、有期限的待追蹤），我決定要不要加入。
2. **順路可以補**：依 4.3 篩選、依總分排序。每家顯示推薦理由、倍數條、待追蹤條。店名點擊開 A8。
3. **順序與時間**：小地圖、排序後的站點與抵達時間、總距離、車程、**預估收工時間**（頁首也顯示，超過 17:30 標紅）。按「確定，送到手機外勤模式」。

錨點來源：手動輸入；訂單主檔「貨運公司」為**業務親送**且當天要送的單自動帶入。

路線排序沿用 `tasks-page.html` 現有的 Google Maps 路線最佳化，**移除油費計算**。

### 5.3 A9 今天（地圖）

A1 的另一種檢視，A1 頁首有「清單／地圖」切換。兩者共用同一份勾選結果。

- 每家店是一個點，顏色依 4.4；開發中的店為空心圓；錨點畫 2 公里虛線圈。
- 點一下跳出小卡：名稱、階段、倍數、距錨點距離，按鈕「加入」「看檔案」。
- 左側浮動面板為當天路線。

### 5.4 A8 藥局檔案（右側抽屜）

從任何頁面點店名或主選單「找藥局」打開，不換頁。由上到下：

- 店名、階段、店家代號、區域、藥師；按鈕：加入今天（一定要去）、加入今天（順路）、延後、打電話。
- A 為什麼推薦：倍數、待追蹤件數與最近期限、今天的規則判定。
- B 待追蹤（可勾選、新增）。C 店家規則（可新增）。
- D 拜訪前簡報：**沿用現有功能**（讀最近 8 筆紀錄，由 Worker 摘要）。
- E 拜訪紀錄（最近 4 筆）。F 進貨（近 12 個月長條、常進品項）。
- G 漏斗歷程：新店展開各階段日期；正式客戶只顯示一行。

### 5.5 A4 規則衝突

只在「擋住」類規則被觸發、且我嘗試加入時跳出。選項：

1. 放進待追蹤（下次路線經過、且不違規時自動推薦）。
2. 指定某一天（打開日曆，禁止日不可選）。
3. 今天例外加入（必須寫一句原因，寫入拜訪紀錄備註）。

**系統不自動決定改到哪一天**，只給選項由我挑。

### 5.6 A5 本週

- 七天一列。每天：日期、假日標記、天氣（溫度、降雨機率，60% 以上標紅）、「這天跑哪區」、指定日期的事、系統提示（例：補假日先確認店家有沒有開；下雨天排停車方便的店）。
- 頂部色帶：請款期、寄單期。請款期顯示待收家數與金額。
- 右側「這週要做的」：還沒指定日期的請款、有期限的待追蹤、逾期沒去的店，可拖到某一天。
- 每天有「規劃這天的店」連到 A1（規劃日設為那天）。
- **週曆只排區域，不排店家**。店家留到當天早上在 A1 決定。

### 5.7 A6 本月

- 月曆方格。過去的日子依當天拜訪家數深淺（7 家以上／4～6／1～3／休息假日）；今天外框；未來日子顯示預計區域與降雨提醒；格子底部色帶標週期。
- 右側本月累計：拜訪次數、覆蓋客戶數、陌生開發數、請款進度、寄單狀態、這個月還沒去過的客戶數（連到 A7）。

### 5.8 A7 客戶總覽

- 上方一排漏斗階段，各顯示家數、建議間隔、超過的家數。
- 下方依城市分組的格子，顏色依 4.4，格內顯示店名與倍數；開發中的店左上角標「發／初／二／試」；已排進今天路線的有外框。

### 5.9 A10 新店開發

- 頂部：開發中家數、卡住家數、近 90 天轉正式家數、發現到第一張正式單的平均天數；期間切換 30 天／90 天／今年。
- 欄位：發現、初訪後、二訪後、試賣中、轉正式、放棄。每欄顯示建議間隔與轉換率。
- 卡片：店名、區域、已幾天、倍數（超過 1.0 紅框）、下一步；按鈕「排進某天」「記結果」。
- 「記結果」：選往下一階段／維持／放棄（放棄要填原因），同時寫入拜訪紀錄一筆、更新篩選分頁的階段欄位。轉正式時另在新客戶資料表建立該店。

### 5.10 A2 店家規則、A3 待追蹤

- A2：左側店家清單（篩選：有規則、待確認、全部）；右側該店規則卡；新增規則先選類型；「從拜訪紀錄找到的可能規則」由 AI 掃描拜訪紀錄與語音筆記，我點一下確認加入。
- A3：篩選（未完成、有期限、下次經過、已完成）；隨手新增列；表格欄位：藥局、事項、誰交代、期限、距上次拜訪、規劃加分。

## 6. 導覽與切換

### 6.1 主選單

每頁頂端，白底、下方細分隔線，高度 56px：

```
SmartRoute ｜ 今天・本週・本月・客戶[46]・新店開發[5] ｜ 管理：店家規則・待追蹤[3] ｜ 規劃日 10/26 週一 ｜ [找藥局]
```

紅色數字徽章：客戶 = 倍數 ≥ 1.0 的家數；新店開發 = 卡住家數；待追蹤 = 3 天內到期件數。為 0 時不顯示。

### 6.2 切換規則

1. **共用規劃日**：今天、地圖、本週、本月共用一個規劃日，放在網址參數（`?date=2026-10-26`），顯示在主選單。預設今天。
2. **往下鑽**：本月點某週 → 本週；本週點「規劃這天的店」→ 今天，且規劃日改為那天。**往上**一律點主選單。
3. **店名一律開抽屜**：不換頁，關閉後回到原位置與捲動。抽屜內的「加入今天」作用於目前規劃日。
4. **清單／地圖記住上次選擇**（localStorage，讀寫要 try/catch）。
5. **規則只在加入時檢查**：瀏覽時只做標示，加入時才跳出 A4。
6. **預設開啟頁**：電腦一律開「今天」。路線確定後「今天」變唯讀並顯示「已送到手機」，要改需按「重新規劃」。

## 7. 手機版（之後另外設計，現在先遵守）

手機外勤模式會在電腦版完成後另外設計。現在做電腦版時遵守以下原則，避免之後要重寫：

1. **資料邏輯和畫面分開**：評分、篩選、規則判定、路線排序都寫在 Worker 或獨立的 JS 模組，不要寫在頁面的 DOM 操作裡。手機版會呼叫同一組 API。
2. **API 回傳完整的判定結果**：例如推薦清單直接回傳 `score`、`ratio`、`reason`、`ruleStatus`，前端只負責顯示。
3. **當天路線存在後端**（不是只在瀏覽器）：電腦按「確定」後，手機打開就能拿到同一份路線。
4. **版面不要在 768px 以下破掉**：電腦版的三欄在窄螢幕可以先直接堆疊，不用特別美化，但不能水平捲動或重疊。
5. 先預留手機版會用到的動作：到店、離店、語音紀錄、跳過這站、打給藥師、結案待追蹤。
