# 方案：A5 本週

> 只寫方案，沒有動手實作。對應使用者 2026-11-02 的工作項目 8，規格依據 `docs/SPEC.md` 5.6
> （七天一列、天氣、假日、寄單/請款色帶、每天跑哪區）。這份方案補上「怎麼做」的技術細節。

## 1. 天氣：中央氣象署開放資料

**申請位置**：https://opendata.cwa.gov.tw/index → 右上角「登入/註冊」→「加入會員」（Email＋
密碼，免費）→ 登入後點「API 授權碼」→「取得授權碼」，立即產生一組授權碼字串。完全免費，不用
綁信用卡，跟 Google Maps 那種要先開帳務帳戶不一樣。

**要用哪個資料集**：「鄉鎮天氣預報」（F-D0047 系列，未來 1 週逐 3 小時/逐 12 小時預報，依鄉鎮
市區查）。業務主要跑新北/台北/桃園/基隆，這幾個縣市的鄉鎮代碼要先對照好（跟健保特約那次處理
縣市代碼的經驗一樣，要注意這是氣象署自己的「鄉鎮代碼」，不是戶政用的標準行政區代碼）。

**怎麼接**：授權碼存成 Worker secret（`CWA_API_KEY`，`wrangler secret put`），伺服器端
（`worker.js`）呼叫，不要放前端（氣象署雖然沒像 Google 那樣會因為 key 外流被扣錢，但還是不要
把授權碼暴露在前端程式碼裡）。天氣資料變動不快（預報每天更新幾次），建議比照「車程」方案
（item 7）的做法，用 Cron Trigger 每天跑 1～2 次，寫進 `TODOS_KV`，A5 載入時直接讀快取，
不要每次開頁面都即時打一次氣象署 API。

## 2. 假日：政府行政機關辦公日曆表（免費、不用註冊）

**資料來源**：政府資料開放平臺「中華民國政府行政機關辦公日曆表」（data.gov.tw dataset 14718），
人事行政總處每年 7～8 月公布隔年全年資料，提供 CSV/XLS 格式，**不用申請任何 key，直接下載**。
包含國定假日、補假、調整放假（補班日）等完整標記。

**怎麼接**：這份資料一年只更新一次（公布隔年份），不需要即時抓取——建議**下載當年＋隔年的 CSV，
手動轉成一份小型 JSON 放進專案（例如 `holidays-2026.json`），每年 7～8 月提醒自己更新一次**，
比每天呼叫一次外部 API 更穩定（不用擔心對方網站改格式或暫時打不通）。如果你不想每年手動更新，
也可以做成 Worker 排程年中自動抓一次，但考量一年只需要做一次，手動更新的維護成本其實更低，
這點等你決定。

## 3. 寄單期／請款期色帶

**寄單期**：SPEC 已經寫明是每月 1～5 日，這是固定的行事曆規則，不需要任何外部資料，前端直接用
日期判斷（`day >= 1 && day <= 5`）。SPEC 第 11 節待辦提到「寄單期對外勤路線有沒有影響」還沒決定
——**這份方案先只做「色帶顯示」，不影響路線限制或排店邏輯**，等你實際用過覺得需要擋什麼再加。

**請款期**：SPEC 沒有明確定義是每月哪幾天，需要你告訴我這個週期的規則（例如固定幾號到幾號？
還是依每家店合約各自的請款日？）我才能照樣做色帶判斷。**這是這份方案唯一需要你補規則的地方**，
其餘（待收家數與金額）已經有資料來源可以算：合約資料（`SHEET_CONTRACT`）＋寄賣中訂單
（跟 A8 分級用的 `consignmentAllTotal` 同一套算法）。

## 4. 每天跑哪區

**沿用項目 7「今天可以跑的區」同一套區域資料**（新店家數/最高倍數、送貨家數、客戶該去家數、
車程），不是另外設計一套。A5 跟 A1 的差別只在「A5 看的是未來一週的概況，A1 看的是今天」——
資料模型應該共用，顯示方式不同。

**「規劃這天的店」要怎麼記住選了哪一區**：`/api/plan` 的 POST（`handleSavePlan`）已經會把
每一天的錨點/路線存進 `TODOS_KV`（Phase 2 既有機制）。建議直接在同一筆每日存檔資料裡**多加一個
`region` 欄位**（純 KV 裡的資料結構增量，不是 Google Sheet schema，沒有 AppSheet 限制），
A5 選了某天要跑哪區時寫進去，A1 開啟那一天時可以讀到、預先標示（但不強制，你到了 A1 當天還是
可以重新選）。

## 6. 待你確認的問題

2. 天氣／車程都建議走「排程預先算好存 KV」而不是即時呼叫——這表示需要在 `wrangler.toml` 加
   Cron Trigger（目前這個 Worker 還沒用過排程功能）。這個決定會同時影響項目 7 跟這項，要不要
   一次設好排程基礎建設，兩個方案一起做？
3. 假日資料要我手動下載轉存 JSON（一年更新一次），還是要做成自動排程抓取？
