# 方案：寄賣滿 7 個月自動產生請款待追蹤

> 只寫方案，沒有動手實作。對應使用者 2026-11-02 的工作項目 9。這項會**自動寫入待追蹤表**，
> 是這次 11 個項目裡少數會動到正式資料的，所以要先寫方案給你確認，不直接做。

## 現況（已經有的邏輯，這次只是把「顯示」變成「寫入」）

`worker.js` 的 `handlePlannerPlan`（`/api/plan`）現在每次呼叫都會即時算一次「寄賣整理」提醒：
掃「訂單主檔」裡「紅單實體狀態＝寄賣中(資料夾)」的訂單，沒有合約的店用天數規則——訂單日期距今
`>= PLANNER_CONFIG.consignmentCleanupMonths`（目前設 7）個月，彙整成「寄賣N張待整理，最久N個月」
顯示在 A1「建議加入」清單裡。**這個結果目前只存在於當次 API 回應，沒有寫進任何分頁**，所以你每次
開 A1 都要重新看一次這份清單，自己判斷要不要處理。

這次要做的是：把這個判斷結果**真的寫進「待追蹤」分頁**，變成「待追蹤」頁（A3）跟 A1 徽章都看得到
的正式事項，不用每次靠 A1 的「建議加入」清單提醒自己。

## 核心問題：怎麼避免重複產生

「待追蹤」分頁（`gas-backend` 的 `PlannerSetup.js`）目前欄位是：
`待追蹤ID／店家代號／事項／誰交代／期限類型／期限／建立日期／狀態／完成日期／完成來源`

沒有任何欄位直接對應「這筆待追蹤是為了哪一張寄賣訂單產生的」，如果每次排程都重新掃一次寄賣中
訂單、看到還沒處理的就建一筆，會重複建出好幾筆一模一樣的待追蹤。這份方案提出兩種避免重複的作法：

### 作法 A（建議）：待追蹤分頁加一個「來源識別碼」欄位

「待追蹤」分頁**不是 AppSheet 管理的表**（AppSheet 管理的只有新客戶資料表、拜訪紀錄、訂單主檔
這三個，不在這次新增欄位的限制範圍內），可以安全加一個新欄位，例如 `來源參照`，存一個穩定的
識別碼（例如 `店家代號 + 訂單日期`，像 `C133-20260618`）。排程產生待追蹤前，先查這個分頁有沒有
`來源參照` 相同、狀態還是「未完成」的既有列，有就跳過不重複建立；該筆訂單如果之後被處理掉
（對帳/出貨完成），待追蹤本身用現有「完成」流程結案即可，之後同一張訂單不會再觸發（因為訂單
狀態應該也會跟著變，不再是「寄賣中(資料夾)」）。

**優點**：判斷直接、穩定，不怕事項文字被使用者手動改過而比對不到。
**缺點**：要先請你手動在「待追蹤」分頁加一欄（或我寫一次性腳本加欄位，比照階段歷程分頁的建立
方式），多一道設定步驟。

### 作法 B：用「店家代號＋事項文字」比對，不加欄位

排程產生待追蹤前，查這個店家代號現有「未完成」的待追蹤裡，「事項」文字裡有沒有已經包含
「寄賣待整理」這個關鍵字樣的既有列，有就跳過。

**優點**：不用改分頁結構，現在就能做。
**缺點**：比對比較脆弱——如果使用者手動編輯過「事項」文字、或同一家店剛好同時有兩種不同的寄賣
提醒，判斷可能誤判（漏建或重複建都有可能）。而且沒辦法精準對應到「是哪一批訂單」，只能用
「這家店目前有沒有未結案的寄賣提醒」這種粗略判斷——如果店家先前有 3 張寄賣單都滿 7 個月、
一次性建了一筆彙總待追蹤，後來又多一張新的滿 7 個月，沒辦法只針對新的那張再提醒。

**建議選作法 A**，雖然多一道設定，但長期判斷更可靠，這個工具本來就是要長期穩定運作的系統，不是
一次性腳本。

## 觸發機制：什麼時候跑

不建議掛在使用者每次打開 A1 的當下即時判斷要不要寫入（使用者只是在看頁面，不應該有寫入副作用，
也會讓 `/api/plan` 回應變慢、變複雜）。建議用 Cron Trigger（跟項目 7／A5 車程/天氣方案一樣，
需要在 `wrangler.toml` 新增排程設定，這個 Worker 目前還沒用過這個功能）：

- 每天跑一次（例如凌晨），掃一次所有沒合約、寄賣滿 7 個月的訂單。
- 新發現滿 7 個月、且沒有既有未結案待追蹤（用上面作法 A/B 判斷）的，呼叫 `gas-backend` 既有的
  `addStageHistory`／`addFollowup` 同類寫入 action（待追蹤已經有現成的新增 action，`handleRule`/
  `addFollowup`，這裡不用新發明一條，只是改成「系統自動呼叫」而不是「使用者按按鈕呼叫」）。
- 寫入內容：`誰交代＝帳務`（延續你之前討論的慣例）、`事項＝「寄賣整理：N張，最久N個月，共$N」`、
  `期限類型＝下次經過`（比照現有邏輯，不是指定日期，因為「下次經過」才會在 A1 自然浮現，不用你
  特地排一天去做）。

## 失敗該怎麼辦（這點也要先講清楚）

排程是背景執行，沒有人在看，如果某一步失敗（例如 GAS 暫時連不上），不能讓它默默消失也不能讓它
无限重試——建議：排程執行結果（成功幾筆、失敗幾筆、失敗的店家代號）寫一行到 Worker 的
log（`wrangler tail` 能看到，或進一步做成失敗時寫一筆到 KV，A1/A5 開啟時如果看到有排程失敗
記錄，用一個不顯眼的提示讓你知道「昨晚有 N 筆自動產生請款待追蹤失敗，店家：xxx」）。這塊細節
可以等真的要做的時候再談，这裡先列出來讓你知道「自動化排程不等於不會出錯，需要有失敗能見度」。
